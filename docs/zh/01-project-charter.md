# 立项文档

> 语言：**中文** · 日本語（翻译中） · English（翻译中）
> 状态：草案 v0.3 · 更新：2026-09-16 · 可视化版本：[charter.html](../charter.html)（本地用浏览器打开）

## 1. 一句话

**StyleAI v2 是一位和你共用衣橱的穿搭博主。** 它懂色彩与层次，读得懂你上传的每件衣服，会去品牌官网找单品，自己写提示词、自己决定怎么分阶段出图，并通过阅读时尚杂志不断学到新技巧。

## 2. 背景

Hackathon demo（[HackathonPJT · deploy/lite-budget](https://github.com/ailuruschen-bit/HackathonPJT/tree/deploy/lite-budget)）验证了“上传衣服 → 数字人试穿出图”的链路，也暴露了几个问题：

| demo 中的发现 | 对 v2 的影响 |
| --- | --- |
| 用户本人数字人需要照片与身体参数，门槛高，隐私压力大 | v2 不收集身材数据，统一使用内置模特 |
| 试穿效果依赖大量手写提示词，每换一种姿态、一种服装都要调 | v2 的提示词由 Agent 根据方案现写 |
| 生成式抠图与试穿会改变服装细节，提示词里不得不写“严禁臆造花纹” | v2 入库改用分割模型，效果图与真值图对比检查 |
| “试穿”只回答了“穿上什么样”，没有回答“该怎么搭” | v2 的核心从试穿转向造型建议 |

## 3. 愿景与定位

v2 的重心从**试穿**转向**造型**：告诉用户怎么穿、为什么这样穿好看，再用专业模特效果图证明这件事。

它像一位用户信任的穿搭博主：懂专业知识，说话真诚，愿意陪用户聊，而且熟悉用户衣柜里的每一件衣服。

### 产品原则

1. **先用用户已有的衣服。** 推荐顺序是“衣橱里的单品 → 衣橱单品 + 少量新品 → 完整新造型”。购物建议是补充，不是目的。
2. **每个建议都讲得出理由。** 配色为什么成立、层次为什么这样安排、引用了哪条技巧，都要说清楚。
3. **不评判身材，也不假设身材。** 不收集身材数据，不说“显瘦”“遮肉”这类话，只讨论衣服之间的关系与穿法。
4. **真诚优先于讨好。** 用户想要的组合不成立时，直接说明原因，并给出可行的调整。
5. **惊喜要有依据。** 非常规穿法（绑腰、单袖穿、外套披肩）必须基于衣服的实际属性提出，并说明效果。

## 6. 范围

**做**

- 与用户多轮深入对话，理解场合、心情和想尝试的风格；界面与对话支持中日英三语
- 用户上传服装照片 → 抠图、分析、打标、入库，形成共享衣橱；用户可以修正标签
- 检索品牌日本官网的经典款与新品，和用户衣橱混搭
- 给出完整方案：单品、层次、配色逻辑、穿法与理由，引用技巧卡
- 用内置模特生成专业效果图，复杂方案多阶段生成并自检
- 记住用户明确表达的偏好与禁忌，用户可以查看和删除
- 从时尚杂志中提炼技巧，经评测与人工审核后并入知识库

**不做**

- 收集或使用用户身材数据
- 生成用户本人形象，或基于用户照片的数字人
- 站内下单与支付（只跳转品牌官网）
- 订单导入与电商账号授权
- 原生移动 App
- 预先写死的提示词模板
- 社交功能（关注、分享社区、评论）

## 7. 核心能力

### 7.1 KNOW · 穿搭知识内核

**用户价值**：方案背后有系统化的专业知识，讲得出理由，而不是凭感觉。

- 知识以“技巧卡”保存，覆盖色彩（色相环配色、明度与彩度层级、中性色比例）、层次（内 / 中 / 外 / 点缀四种角色，长短、厚薄、松紧的交替）、廓形与比例（H / A / V / X 廓形、上松下紧、腰线位置）、材质与图案（质感对比、图案大小搭配、正式度统一）。
- 知识库 v1 由人工整理约 150 张技巧卡，覆盖以上四类，每类不少于 25 张。
- 每个方案必须引用至少一张技巧卡，界面上可以展开查看。

**验收**：造型师抽查 30 个方案，引用的技巧卡与方案内容相符的比例 ≥ 90%。

### 7.2 CLOSET · 衣橱理解

**用户价值**：上传一张照片，衣服就被准确地记录下来，不需要手动填写。

- **输入**：平铺或挂拍的服装照片，JPEG / PNG / HEIC，单张不超过 15 MB。
- **处理**：分割抠图 → 质量检查 → 颜色提取 → 视觉打标 → 向量化。质量检查不通过时，告诉用户具体原因（衣服没拍全、画面里有多件衣服、照片模糊等）。
- **标签字段**：类目与子类目、主色与点缀色（hex、占比、三语名称）、材质、图案、廓形、衣长、正式度（1–5）、季节、风格标签、玩法潜力。
- **玩法潜力**：根据类目与属性判断可行的非常规穿法，例如带袖子的卫衣与衬衫可以绑腰，前开襟上衣可以单袖穿或敞开当外套，针织开衫可以披肩，长款 T 恤可以塞一角。
- **修正**：用户可以修改任何标签；被修改过的字段不再被自动覆盖，修正记录进入评测数据。

**验收**：200 件标注集上，类目、主色、材质、廓形的准确率 ≥ 90%；从上传到入库完成 P50 ≤ 20 秒。

### 7.3 SCOUT · 品牌单品探索

**用户价值**：知道“买什么”能和已有的衣服配起来，而且链接真实可买。

- 定期巡检首批 5 个品牌日本官网的商品，区分经典款与当季新品，保存为品牌目录。
- 对话中目录结果不足时，Agent 在品牌官网域名范围内检索，并把找到的商品加入目录。
- 推荐只能引用目录中存在且在售的商品；价格以日元显示，附官网链接与抓取时间。

**验收**：推荐时链接可访问且在售的比例 ≥ 98%。

### 7.4 COMPOSE · 搭配方案生成

**用户价值**：得到一套完整、可以直接照着穿的方案。

- 结合对话中的场合与偏好、用户记忆、衣橱、品牌目录与技巧卡生成方案。
- 生成后先用规则检查配色与层次是否自洽，再保存和生图。
- 一次对话通常给出一个稳妥方案；在合适时附加一个“意外但成立”的方案，并说明它为什么成立。

方案卡片包含：

| 部分 | 内容 |
| --- | --- |
| 标题与场合 | 例如“代官山周末 · 休闲但有精神” |
| 单品列表 | 每件单品的图片、来源（衣橱 / 品牌）、层次角色、穿法（如“绑在腰间”） |
| 配色说明 | 用到的颜色与关系，例如“麻灰打底，藏青胸标与深蓝牛仔裤呼应” |
| 理由 | 为什么这样搭好看，引用的技巧卡 |
| 可替换单品 | 衣橱中可以替换的单品，或可以购买的品牌商品 |
| 效果图 | 生成中显示阶段进度，完成后显示最终图 |

**验收**：造型师盲评方案专业度均分 ≥ 4.0 / 5。

### 7.5 RENDER · 自主生图编排

**用户价值**：看到这套方案穿在模特身上的真实效果。

- 提示词由 Agent 根据方案现写；简单方案一次成图，复杂方案（多层叠穿、非常规穿法）规划为多个阶段。
- 每个阶段完成后立即显示在方案卡片上；最终图经过检查：单品是否正确、颜色是否还原、穿法是否做到、人体结构是否自然。
- 输出规格：3:4 画幅，全身入画，棚拍柔光，无缝浅色背景。
- 生成失败不扣额度，可以重试。

**验收**：服装还原度人工评分 ≥ 4 / 5 的效果图占比 ≥ 80%；单阶段首图 P50 ≤ 40 秒，多阶段 P50 ≤ 120 秒。

### 7.6 LEARN · 自我迭代学习

**用户价值**：穿搭建议跟得上季节和潮流，而不是一成不变。

- 后台每周读取已批准来源的新文章，提炼候选技巧卡。
- 候选卡经过照抄检查、去重、评测回归、人工审核，才会进入正式知识库。
- 趋势类技巧带有效期，过季后自动降低权重。

**验收**：合入新卡后评测分不下降；候选卡审核通过率按来源统计，用于调整来源。

## 8. 对话体验

### 8.1 Agent 的说话方式

| 要求 | 说明 |
| --- | --- |
| 语言 | 跟随用户使用的语言（中文、日文、英文）；日文使用亲切的です・ます体 |
| 语气 | 亲切、专业、直接，像熟悉的造型师朋友；不用过多的感叹号和表情符号 |
| 提问 | 信息不足时先提问，一次只问一个最关键的问题 |
| 解释 | 专业术语第一次出现时用一句话解释 |
| 边界 | 不评判身材；不对用户的审美下否定结论，而是说明组合的效果 |
| 不确定时 | 明确说明，例如效果图中某个细节没有完全还原 |

### 8.2 一段示例对话

> **用户**：明天去代官山逛街，想用我那件灰色卫衣，别再配黑裤子了。
>
> **StyleAI**：好，我先看看你衣橱里有哪些能和它搭的。……你有一条靛蓝直筒牛仔裤和一件白色长袖 T 恤，这件卫衣的藏青胸标正好能和牛仔裤的蓝色呼应。
>
> 我准备了两个方案：
>
> **方案一 · 稳妥**：白 T 打底，灰卫衣正常穿，靛蓝牛仔裤卷一折露出脚踝，配白色板鞋。整体是“中性色 + 一个蓝色”，清爽不出错。
>
> **方案二 · 换个玩法**：把卫衣绑在腰间，上身只穿白 T，外面加你那件卡其色工装夹克。卫衣绑腰会在腰部形成一个灰色的色块，把上下身分开，比例会更利落，也更有街头感。明天白天 22 度左右，热了可以脱夹克，冷了可以把卫衣穿上。
>
> 两个方案的效果图正在生成，第二个是多阶段生成，需要一两分钟。

（示例用于说明语气与信息组织，不代表实际输出。其中的天气信息需要接入天气数据，列为后续需求。）

## 9. 内置模特库

- 用允许商用的生图模型生成“不存在的人”。每位模特有一组参考图（正面、侧面、四分之三身，基础白 T 与浅色长裤），作为每次出图的身份参考。
- 上线前做真人与名人相似度筛查，模特卡记录生成模型、日期、许可条款与筛查结果。
- 首批 4 位（M0），扩充到 12 位（M3）。男女皆有，覆盖多种风格原型与族裔构成。
- Agent 按方案风格挑选模特，用户也可以指定。

| 设备 | 桌面与手机浏览器（最新两个主要版本的 Chrome、Safari、Edge） |
| 成本 | 每轮对话、每个方案有 token 与生图次数上限；单方案成本目标在 M0 实测后确定 |

## 12. 风险与合规

| 风险 | 等级 | 对策 |
|---|---|---|
| 杂志内容版权 | 高 | 只提炼抽象技巧并重写，保存出处，不存原文与图片；照抄检查；确认订阅服务条款 |
| 品牌官网抓取与商品图使用 | 高 | 优先联盟渠道；遵守 robots 与条款；只存元数据与链接；效果图标注示意 |
| 大型品牌官网反爬导致数据不稳定 | 高 | M0 起调研联盟渠道；无法合规获取的品牌从首批中替换 |
| 模特肖像与生成图版权 | 高 | 商用许可的生图模型；相似度筛查；记录来源与许可 |
| 用户图片发送给第三方模型服务 | 高 | M0 确认各服务的数据使用条款；隐私政策明确告知 |
| 外部网页中的提示词注入 | 中 | 网页内容只提取结构化字段，不拼入系统提示词；工具权限限定在当前用户 |
| 服装还原失真 | 中 | 分割抠图保留原像素；多阶段编辑 + 与真值图对比检查 |
| 非常规穿法出图失败 | 中 | 拆成独立阶段；沉淀生图经验 |
| 知识库跑偏或过时 | 中 | 候选 → 评测 → 人审；趋势类技巧带有效期 |
| 品牌商品幻觉 | 中 | 服务层校验：只能引用目录中的在售商品 |
| 单方案成本过高 | 中 | 简单方案单阶段；后台用小模型；提示缓存；成本上限 |

## 13. 成功指标（初版，M0 后校准）
