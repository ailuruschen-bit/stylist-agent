# 评测：怎么知道这次改动是变好了还是变差了

> 语言：**中文** · 日本語（翻译中） · English（翻译中）
> 所属：[技术原理](README.md) · 更新：2026-09-16 · 实验代码：[labs/eval-stats](../../tech-notes/labs/eval-stats/)

《开发规范》里有一条要求：**改动提示词或工具的 PR，必须附上评测结果。**

这条要求看起来理所当然，执行起来却有一堆问题：拿多少个方案来测？谁来打分？分数差 0.1 算不算变好？如果我自己看了十个方案觉得不错，为什么不够？

本文先说清楚该测什么、有哪几种测法，再用一个模拟实验回答最关键的问题：**多少样本才足以支撑“这次改动更好”这个结论。**

实验用模拟数据，不调用任何模型。模拟的是评测中真实存在的两种噪声：不同的搭配难度不同，同一个方案两次打分也不完全一样。

## 先决定测什么

评测的第一步不是选工具，而是**把“变好了”翻译成一个能测量的量**。StyleAI 的四类指标，测量方式差别很大：

| 指标 | 有没有标准答案 | 测量方式 | 特点 |
| --- | --- | --- | --- |
| 衣橱打标准确率 | 有（人工标注集） | 自动比对 | 客观、可重复、改一次代码就能跑 |
| 品牌链接有效率 | 有（访问一下就知道） | 自动检查 | 完全客观 |
| 服装还原度 | 有参照物（真值图），但没有标准分数 | 人工评分 1–5 | 主观但有依据，评委间一致性较高 |
| 方案专业度 | 没有 | 造型师盲评 1–5 | 最主观，噪声最大 |

**能自动判定的指标要优先建立**，因为它们可以在 CI 里每次运行，成本接近零。需要人打分的指标运行一次就是一次成本，所以要精心设计，用在真正重要的判断上。

## 三种评测方式

### 1. 有标准答案的自动评测

准备一个标注集：200 件衣服，每件的类目、主色、材质、廓形由人工标注好。每次改动后，跑一遍打标，和标注比对，得到准确率。

要点：

- **标注集要固定下来。** 中途修改标注集，前后的分数就不能比较了。确实需要修改时，记录版本和修改原因。
- **标注集要覆盖难例。** 全是白衬衫的标注集测不出什么；要包含麻灰、渐变、拼色、透明材质、复杂印花。
- **标注本身也会错。** 准确率 92% 时，先看看错的 8% 里有多少是标注错了。

### 2. 人工盲评

给评委看结果，但不告诉他们这是哪个版本产生的。StyleAI 的方案专业度、服装还原度都用这种方式。

要点：

- **盲**：版本信息必须隐藏，否则“我知道这是新版本”本身就会影响打分。
- **打分标准要写出来。** 1 分到 5 分分别意味着什么，要有例子。否则不同评委、甚至同一个评委在不同时间的标准都不一样。
- **成对比较往往比打分更稳。** “A 和 B 哪个更好”比“这个方案几分”更容易保持一致。

### 3. 用模型当评委

人工评测贵且慢，所以常用一个模型来打分，也就是 LLM-as-judge。它便宜、快、可以随时重跑，但有几个已知的偏差：

| 偏差 | 表现 | 对策 |
| --- | --- | --- |
| 位置偏差 | 成对比较时，偏向排在前面（或后面）的那个 | 每个样本正反各评一次，或随机交换顺序 |
| 冗长偏好 | 更长、更详细的回答得分更高，即使内容没有更好 | 评分标准里明确说明长度不是加分项；必要时控制输出长度 |
| 自我偏好 | 倾向于给同一家模型生成的内容打高分 | 评委模型与被评模型分开；关键判断用人工复核 |
| 分数堆积 | 大部分样本都是 4 分，区分度低 | 改用成对比较，或要求给出具体扣分理由 |

**模型评委必须先和人工标注校准。** 做法是：取 50 个样本，人工评一遍，模型评一遍，计算两者的一致程度。一致性达标之后，模型评委才可以用于日常判断；一致性不达标，说明评分标准写得不清楚，先改标准。

## 实验：20 个样本够不够

模拟一个具体的问题：提示词 v2 比 v1 真的好 0.2 分（3.90 对 4.10，满分 5 分）。我们不知道这个真实差距，只能通过评测去估计它。

模拟中包含两种噪声：搭配本身的难度差异（标准差 0.7）、同一个方案打分的随机波动（标准差 0.45）。

先看五次独立的评测，每次 20 个方案，两个版本各用不同的方案：

```text
[1] one eval with 20 items, different items per version
  run 1: observed difference +0.194  -> v2 looks better
  run 2: observed difference +0.009  -> v2 looks better
  run 3: observed difference -0.111  -> v1 looks better
  run 4: observed difference +0.267  -> v2 looks better
  run 5: observed difference +0.563  -> v2 looks better
```

同一个真实差距 +0.20，五次评测给出了从 -0.111 到 +0.563 的结果。**第 3 次直接指向了错误的结论，第 5 次把差距夸大了近三倍。** 如果只跑一次就下判断，得到的很可能是噪声。

那么跑多少个样本才够？实验 [2] 重复模拟 4000 次，统计“评测指向了更好的版本”的比例：

```text
[2] how often the eval points at the better version
   items   unpaired    paired
      10     70.4%     83.5%
      20     77.5%     91.9%
      50     87.8%     98.0%
     100     95.2%     99.9%
     200     99.0%    100.0%
     500    100.0%    100.0%
```

“unpaired”一列是两个版本各用不同方案的做法：**20 个样本时，有 22.5% 的概率得出相反的结论。** 这就是“我看了十个感觉不错”不能作为依据的原因。

## 配对：同一批场景，两个版本各跑一遍

“paired”一列的做法不同：**同一批场景，两个版本各跑一遍，比较每个场景上的差值。**

效果很明显：20 个样本的配对评测（91.9%）比 50 个样本的非配对评测（87.8%）还要可靠。

原因是噪声的来源变了。非配对评测里，两组用的是不同的场景，场景难度的差异（标准差 0.7）全部混进了结果；配对评测中，同一个场景的难度对两个版本是一样的，相减就抵消了，剩下的只有打分波动。

**用一半的样本得到更可靠的结论，代价只是每个场景要多跑一次。** 对 StyleAI 来说，这意味着评测集要保存的是“场景”（用户需求 + 衣橱状态），而不是某一次生成的结果。

实验 [3] 把判定标准收紧，要求观察到的差距超过 0.05 才算数，结论不变：配对设计在各个样本量上都更可靠。

## 报告要带区间，不能只报均值

实验 [4] 对单次配对评测计算自助法（bootstrap）置信区间——把已有的差值重复有放回抽样，看均值的分布范围：

```text
[4] bootstrap 95% confidence interval of the paired difference (one eval each)
  n=  20  mean -0.033  CI [-0.313, +0.259]  width 0.572  includes 0
  n=  50  mean +0.135  CI [-0.023, +0.300]  width 0.323  includes 0
  n= 100  mean +0.204  CI [+0.091, +0.317]  width 0.226  excludes 0
  n= 200  mean +0.182  CI [+0.095, +0.268]  width 0.174  excludes 0
  n= 500  mean +0.189  CI [+0.130, +0.244]  width 0.114  excludes 0
```

n=20 那一行值得注意：均值是 -0.033，看起来 v2 更差，但区间从 -0.313 到 +0.259，**包含 0，也包含真实值 +0.20**。正确的结论不是“v2 更差”，而是“这次评测什么也没说明”。

到 n=100，区间才排除 0，可以说“v2 确实更好”；区间宽度随样本量缩小，但缩小得越来越慢——从 20 到 100 宽度减半，从 100 到 500 才再减半。

**所以评测报告要写成“+0.20，95% 区间 [+0.09, +0.32]”，而不是“4.10 分 vs 3.90 分”。** 后者会让人误以为差距是确定的。

## 多一个评委，相当于多一些样本

实验 [5] 把打分改成两个评委的平均：

```text
[5] averaging two judges instead of one (paired design)
   items   1 judge   2 judges
      20     91.9%     97.2%
      50     98.0%     99.9%
```

平均两个评委的分数，把打分波动的标准差降到约原来的 1/√2，可靠性因此提高。这给了一个实际的权衡：**增加评委和增加样本都能提高可靠性，选哪个要看哪种成本更低。** 模型评委便宜，多评几次很容易；造型师的时间贵，更适合把有限的人力用在样本量上。

## StyleAI 的评测集

| 评测集 | 规模 | 内容 | 判定方式 | 运行时机 |
| --- | --- | --- | --- | --- |
| `tagging-200` | 200 件衣服 | 照片 + 人工标注的类目、颜色、材质、廓形 | 自动比对 | 每次相关 PR |
| `smoke-20` | 20 个场景 | 覆盖五类使用场景的对话 | 自动检查 + 模型评委 | 每次提示词或工具改动 |
| `outfit-quality-100` | 100 个场景 | 用户需求 + 衣橱快照 | 配对盲评（造型师或模型评委） | 里程碑、重要改动 |
| `render-fidelity-50` | 50 个方案 | 方案 + 真值图 | 人工评分 1–5 | 里程碑、换生图模型 |
| `links-auto` | 全量目录抽样 | 品牌商品链接 | 自动访问 | 每天 |

每个评测集都有版本号；场景以“需求 + 衣橱快照”的形式保存，保证两个版本跑的是同一批输入。

## 别在评测集上过拟合

反复用同一批样本调提示词，分数会越来越好，但很可能只是把这批样本的特点背了下来。做法是把场景分成两部分：

- **开发集**：日常调试随便用，跑多少次都行；
- **保留集**：只在里程碑和重要决策时跑，跑完记录结果，不根据它反复调整。

如果开发集的分数在涨、保留集不涨，说明改动只是拟合了开发集。此外，提示词里不要写评测集中的具体例子，评测集也要定期补充新场景。

## 在流程里怎么运行

| 时机 | 跑什么 | 谁看 |
| --- | --- | --- |
| 每次提示词 / 工具 PR | `smoke-20` + 相关自动指标 | CI 自动把结果贴到 PR |
| 合入前（影响方案或生图） | `outfit-quality-100` 配对评测 | 作者附结果，审查者确认 |
| 每个里程碑结束 | 全部评测集，含保留集 | 写入 `evals/reports/` |
| 每天 | 链接有效率、线上抽样指标 | 看板与告警 |

每份评测报告必须记录：数据集名称与版本、提示词版本、模型 ID 与参数、样本量、均值与置信区间、总成本。缺少其中任何一项，这份报告在下次改动时就无法作为对照。

## 小结

评测的难点不在跑分，而在**分辨“真的变好了”和“这次运气好”**。模拟实验给出了三条可以直接用的结论：

1. 20 个样本的非配对评测，有超过两成的概率指向错误的版本；
2. 同一批场景配对比较，能用更少的样本得到更可靠的结论；
3. 报告要带置信区间，区间包含 0 时，正确的结论是“这次评测没有结论”。

读完本文，可以试着回答：如果一次改动在 `outfit-quality-100` 上的差距是 +0.06，95% 区间是 [-0.04, +0.16]，这次改动该不该合入？需要补充什么信息才能决定？
