## 1. ひとことで

**StyleAI v2 は、あなたとクローゼットを共有するスタイリストです。** 色と重ね着を理解し、アップロードされた服を一着ずつ読み取り、ブランド公式サイトでアイテムを探します。プロンプトも生成の段取りも自分で決め、ファッション誌を読んで新しいテクニックを学び続けます。

## 2. ビジョンと位置づけ

ハッカソンの demo（[HackathonPJT · deploy/lite-budget](https://github.com/ailuruschen-bit/HackathonPJT/tree/deploy/lite-budget)）では「服をアップロード → バーチャル試着画像」の流れを検証しました。v2 では重心を**試着**から**スタイリング**へ移します。どう着るか、なぜ素敵に見えるかを伝え、プロのモデルによる着用イメージでそれを示します。

- **プロフェッショナル**：配色、レイヤード、シルエットと比率、素材の対比を体系的な知識として持ち、すべての提案に理由を添えます。
- **遊び心**：無難な提案に加えて、腰巻き、片袖抜き、アウターの肩掛けなどトレンドの着こなしも提案します。
- **自律性**：プロンプト、生成手順、ブランド検索はすべて Agent が判断します。テンプレートは用意しません。
- **成長**：ファッションコンテンツを読み続け、新しいテクニックをナレッジベースに蓄積します。

## 4. スコープ

**やること**

- ユーザーと何往復も対話し、シーン、気分、挑戦したいスタイルを理解する
- アップロードされた服を分析・タグ付け・登録し、共有クローゼットをつくる
- ブランド日本公式サイトの定番品と新作を探し、手持ちの服と組み合わせる
- アイテム、レイヤー構成、配色の考え方、着こなし、理由まで含む提案を出す
- 内蔵モデルでプロ品質の着用イメージを生成し、複雑な提案は多段階で生成する
- ファッション誌からテクニックを抽出し、審査を経てナレッジベースに追加する

**やらないこと**

- ユーザーの体型データの収集や利用
- ユーザー本人の画像生成、写真ベースのデジタルヒューマン
- アプリ内での購入と決済（ブランド公式サイトへの遷移のみ）
- 注文履歴の取込と EC アカウント連携
- ネイティブのモバイルアプリ
- 事前に固定したプロンプトテンプレート

## 5. Demo から v2 へ

| Demo の要素 | v2 での扱い | 方針 |
|---|---|---|
| ジョブキューと worker | 考え方は継続し、Procrastinate で再実装。生成パイプラインと登録ジョブを追加 | 強化 |
| SSE の進捗通知 | Agent イベントストリームに拡張 | 強化 |
| NanoBanana アダプタ + self-check | `render_stage` と `render_critique` のツールに分割。プロンプトは Agent が生成 | 強化 |
| 生成モデルによる切り抜き | セグメンテーションモデルに置き換え、服のディテールが変わるのを防ぐ | 置換 |
| 生成ログのデバッグページ | Agent の全工程トレースに拡張 | 強化 |
| ログイン、クレジット、管理画面、三言語 i18n | そのまま継続 | 継続 |
| デジタルヒューマン、ポーズライブラリ、体型パラメータ、注文取込、固定プロンプト | 不要 | 削除 |

## 6. コア機能

| コード | 機能 | ポイント |
|---|---|---|
| KNOW | スタイリング知識 | 色、レイヤード、シルエットと比率、素材と柄。「テクニックカード」として検索・引用できる |
| CLOSET | クローゼット理解 | 切り抜き、タグ付け（色の hex と比率、素材、シルエット、フォーマル度など）、「着こなしポテンシャル」（腰巻き、片袖抜きなど）の判定 |
| SCOUT | ブランドアイテム探索 | ブランド日本公式サイトの定番品と新作を検索しカタログ化。提案ではカタログに実在するアイテムのみ引用 |
| COMPOSE | コーディネート提案 | 対話、クローゼット、カタログ、テクニックカードを組み合わせる。生成前にルール検証。安心できる提案 + 意外だけど成立する提案 |
| RENDER | 自律的な画像生成 | Agent がその場でプロンプトを書く。複雑な提案は多段階に分けて編集とセルフチェック |
| LEARN | 自己学習 | バックグラウンド Agent が雑誌を読み候補カードを作成。評価と人の審査を経て追加 |

## 7. 多段階の画像生成

1. **計画**：複雑さを判断し、構造化された生成計画（段階、参照画像、忠実に再現すべきディテール、チェック項目）を出力。
2. **ベースのスタイリング**：モデル参照画像 + インナーとボトムス。色、柄、シルエットの再現を最優先。
3. **レイヤード**：前段階の結果を編集してアウターを追加。
4. **変わった着こなしとディテール**：腰巻き、片袖抜き、フロントイン、袖まくり、小物を一項目ずつ部分編集。
5. **セルフチェックと修正**（ループ）：計画と照合し、不合格なら該当段階をやり直すか部分修正。リトライ上限あり。

シンプルな提案は一回で生成してからチェックします。

## 8. 内蔵モデルライブラリ

- 商用利用可能な画像生成モデルで「実在しない人物」を生成。モデルごとの参照画像セットで、毎回同じ見た目を保つ。
- 公開前に実在の人物や著名人との類似度をチェックし、生成モデル、日付、ライセンス条件を記録。
- 男女とも揃え、複数のスタイルと多様なルーツをカバー。Agent が提案に合わせて選び、ユーザーも指定できる。
- 出力規格を統一：スタジオのソフトライト、無地背景、全身、3:4。

## 9. マイルストーン

| フェーズ | 週 | 成果物 | 完了条件 |
|---|---|---|---|
| M0 基盤 | W1–2 | 新リポジトリの土台、Agent ループの骨格、モデルライブラリ v0（4 名）、評価セット v0、デプロイ方式とブランドデータ入手経路の調査 | 一文の依頼 → ツール呼び出し → 着用イメージ 1 枚 |
| M1 クローゼット理解 | W3–4 | アップロード → 切り抜き → タグ付け → 登録。着こなしポテンシャルの判定 | 200 着のラベル付きセットで属性精度 85% 以上 |
| M2 コーデの頭脳 | W5–7 | ナレッジ v1（約 150 枚のカード）、提案と理由、対話の人格 | スタイリストのブラインド評価で専門性 4 / 5 以上 |
| M3 画像生成の設計 | W6–9 | 生成計画、多段階、セルフチェックと修正。モデルライブラリ v1（12 名） | 服の再現度 4 / 5 以上の割合が 80% 以上 |
| M4 ブランド探索 | W9–11 | 5 ブランドの日本公式サイトのカタログ、手持ち服とのミックス | 提案リンクの有効率 98% 以上 |
| M5 自己学習 | W11–13 | 雑誌学習パイプライン（P0 ソース）、候補カードの評価と審査 | 新カード追加後も評価スコアが下がらない |
| M6 仕上げとクローズドテスト | W13–15 | コストとレイテンシの最適化、30 名のクローズドテスト（日本のユーザー） | 保存率、再訪率がベースラインに到達 |

開発前の準備期間：本書、「技術選定」「開発規約」「情報ソース一覧」を仕上げ、承認後に M0 に入ります。

## 10. リスクとコンプライアンス

| リスク | レベル | 対策 |
|---|---|---|
| 雑誌コンテンツの著作権 | 高 | 抽象的なテクニックだけを抽出して書き直し、出典を記録。本文と画像は保存しない。購読サービスの規約を確認 |
| ブランド公式サイトの取得と商品画像の利用 | 高 | アフィリエイト経路を優先。robots と規約を順守。メタデータとリンクのみ保存。着用イメージには「イメージ」と明記 |
| 大手ブランドサイトのボット対策によるデータ不安定 | 高 | M0 からアフィリエイト経路を調査。ボット対策の回避は一切しない |
| モデルの肖像と生成画像の権利 | 高 | 商用利用可能な画像生成モデル、類似度チェック、生成元とライセンスの記録 |
| 服の再現崩れ | 中 | セグメンテーションで元のピクセルを保持。多段階編集 + ビジョンによるチェック |
| 変わった着こなしの生成失敗 | 中 | 独立した段階に分ける。生成ノウハウカードを蓄積 |
| ナレッジの劣化や陳腐化 | 中 | 候補 → 評価 → 人の審査。トレンド系は有効期限付き |
| ブランド商品のハルシネーション | 中 | カタログ内のアイテムのみ引用。リンクを定期巡回 |
| 提案ごとのコスト超過 | 中 | シンプルな提案は一段階、バックグラウンドは小型モデル、プロンプトキャッシュ、コスト上限 |

## 11. 成功指標（初期値、M0 後に調整）

| 指標 | 定義 | 目標 |
|---|---|---|
| タグ精度 | ラベル付きセットでのカテゴリ、色、素材、シルエット | ≥ 90% |
| 服の再現度 | 人の評価で 4 / 5 以上の画像の割合 | ≥ 80% |
| 提案の専門性 | スタイリストのブラインド評価 1–5 | ≥ 4.0 |
| 意外な着こなしの採用 | 保存された提案のうち変わった着こなしを含む割合 | ≥ 15% |
| ブランドリンク有効率 | 提案時点でリンクが開けて販売中 | ≥ 98% |
| 最初の画像までの時間 | 一段階 P50 / 多段階 P50 | ≤ 40s / ≤ 120s |
| 提案あたりのコスト | LLM + 画像生成 | M0 実測後に決定 |

## 12. 決定が必要な事項

1. **プロダクト名**：StyleAI v2 は仮称。リポジトリ名は `stylist-agent`。
2. **モデルのラインナップ**：男女比、スタイルの原型、ルーツの構成、最初の 4 名のキャラクター設定。
3. **ビジネスモデル**：クレジット制、ブランドアフィリエイト、サブスクリプションのどれか。ブランドとの協業方法にも影響。
4. **オープンソースライセンス**：現在は公開だがライセンス未付与（All rights reserved）。ビジネスモデル確定後に決める。
