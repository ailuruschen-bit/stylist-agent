立项文档 · 草案 v0.2

一位和你共用衣橱的穿搭博主

StyleAI v2 是一个会思考的穿搭 Agent：它懂色彩与层次，读得懂你上传的每件衣服，会去品牌官网找单品，自己写提示词、自己决定怎么分阶段出图，并通过阅读时尚杂志不断学到新技巧。

愿景与定位

我们在做什么，以及刻意不做什么

像一位懂色彩、懂层次、说话真诚的穿搭博主，打开你的衣柜，陪你聊，然后把最好看的那一套穿给你看。

Hackathon demo 验证了“上传衣服 → 虚拟试穿出图”的链路。v2 的重心从试穿转向造型：价值不在于把衣服贴到人身上，而在于告诉用户怎么穿、为什么这样穿好看，再用一张专业模特效果图证明这件事。

  • 专业：内置色彩搭配、层次构建、廓形比例、材质对比等系统化知识，每个方案都讲得出理由。
  • 会玩：不只给安全牌，也会提出绑腰、单袖穿、外套反穿披肩等潮流穿法。
  • 自主：提示词、生图步骤、品牌检索都由 Agent 自己决定，我们不预写模板。
  • 会成长：持续阅读时尚内容，把新技巧沉淀进知识库。

范围

v2 首个版本的边界

做

  • 与用户多轮深入对话，理解场合、心情、想尝试的风格
  • 用户上传服装 → 分析、打标、入库，形成共享衣橱
  • 检索品牌官网的经典款与新品，和用户衣橱混搭
  • 给出完整方案：单品、层次、配色逻辑、穿法与理由
  • 用内置模特生成专业效果图，复杂方案多阶段生成
  • 从时尚杂志中提炼技巧，经评审后并入知识库

不做

  • 收集或使用用户身材数据（身高、体重、三围）
  • 生成用户本人的形象，或基于用户照片的数字人
  • 站内下单与支付，仅跳转品牌官网
  • 订单导入与电商账号授权
  • 预先写死的提示词模板

核心能力

六项能力，全部以工具的形式交给同一个 Agent 调度

KNOW

穿搭知识内核

把造型师的经验变成可检索、可引用的结构化知识，而不是塞进一段很长的系统提示词。

  • 色彩：色相环配色（同类、邻近、互补、三角）、明度与饱和度层级、中性色比例、冷暖与季节色
  • 层次：内 / 中 / 外 / 点缀四种角色，长短、厚薄、松紧的交替与露出比例
  • 廓形与比例：H / A / V / X 廓形、上松下紧、三七分、腰线位置
  • 材质与图案：质感对比、图案大小搭配、正式度统一
  • 每条知识是一张“技巧卡”，Agent 出方案时必须注明用了哪几张
CLOSET

衣橱理解

用户上传照片后自动抠图、分析、打标、入库。除了常规属性，还会标出这件衣服的“玩法潜力”。

  • 属性：类目、主色与辅色（hex + 占比）、材质、图案、廓形、正式度、季节、风格
  • 玩法潜力：卫衣可绑腰、衬衫可单袖穿或当外套敞开、针织衫可披肩、长 T 可塞一角
  • 用户可以修正标签，修正结果回流为评测数据
SCOUT

品牌单品探索

Agent 自行到指定品牌官网搜索经典款和当季新品，缓存为品牌商品目录，与用户衣橱一起参与搭配。

  • 按需实时检索 + 定期后台巡检（上新、下架、价格变化）
  • 只保存结构化元数据与官网链接，推荐时只能引用目录中真实存在的条目
COMPOSE

搭配方案生成

结合对话中的场合与偏好、衣橱和品牌目录、技巧卡，产出完整方案。

  • 方案包含：单品及层次角色、配色逻辑、穿法细节、为什么好看、可替换单品
  • 规则校验工具先检查配色与层次是否自洽，再进入生图，减少浪费
  • 每次给出一个稳妥方案，并视情况附一个“意外但成立”的方案
RENDER

自主生图编排

提示词由 Agent 根据方案现写。简单方案一次成图，复杂方案（多层叠穿、非常规穿法）由 Agent 规划成多个阶段，逐步编辑并自检。详见“多阶段生图”。

LEARN

自我迭代学习

后台学习 Agent 定期阅读时尚杂志与秀场报道，提炼出新的技巧，写成候选技巧卡。

  • 候选卡须通过评测集回归（方案质量不下降）和人工审核，才会并入正式知识库
  • 只存用自己的话提炼的抽象技巧与出处，不保存原文和图片
  • 趋势类技巧带时效，过季自动降权

多阶段生图

复杂方案的默认流程；Agent 可以按方案增删阶段

  1. 规划读取方案、判断复杂度，输出结构化生图计划：分几个阶段、每阶段用哪些参考图、必须保真的细节、验收要点。
  2. 基础造型模特参考图 + 内层与下装，优先保证颜色、印花、版型还原。
  3. 叠穿在上一阶段结果上编辑加入外层，按方案执行层次顺序与露出比例。
  4. 非常规穿法与细节绑腰、单袖、塞衣角、卷袖、配饰，逐项局部编辑，避免一次改太多导致失真。
  5. 自检与修复视觉模型对照计划逐项核对：单品对不对、颜色准不准、穿法有没有做到、人体结构是否自然。不通过就定位到对应阶段重做或局部修，设重试上限。

简单方案（两三件、没有非常规穿法）直接一次成图再自检。经过验证的阶段拆法会沉淀为“生图经验卡”，供 Agent 下次参考，但不是固定模板。

内置模特库

帅气漂亮、无肖像与版权风险的标准模特

  • 用允许商用的生图模型生成“不存在的人”。每位模特有一组定妆参考图（正面、侧面、四分之三身），作为每次出图的身份参考，保证同一模特前后一致。
  • 上线前做真人与名人相似度筛查；模特卡记录生成模型、日期与许可条款。
  • 阵容男女皆有，覆盖多个风格原型（街头、极简、学院、通勤、优雅等）与多种族裔；Agent 按方案风格挑选，用户也可以指定。
  • 统一出图规格：棚拍柔光、无缝背景、全身入画、3:4 画幅。Demo 调出的“海报级”出图经验作为 Agent 的参考素材。

风险与合规

高风险项须在 M0 阶段给出结论

风险等级对策
杂志内容版权高只提炼抽象技巧并用自己的话重写，保存出处；不存原文与图片；优先使用已订阅或授权的来源
品牌官网抓取与商品图使用高遵守 robots 与使用条款，优先官方 API 或联盟商品源；只存元数据与链接；效果图标注“示意”，商用前谈授权
模特肖像与生成图版权高使用允许商用的生图模型；合成模特做相似度筛查；记录生成来源与许可
服装还原失真（颜色、Logo、印花）中多阶段编辑 + 视觉自检；关键单品局部修复；还原度纳入评测
非常规穿法出图失败中拆成独立阶段；沉淀经过验证的生图经验卡
知识库迭代跑偏或过时中候选 → 评测 → 人审三道关；趋势类技巧带时效
品牌商品幻觉（不存在的链接或价格）中推荐只能引用目录中的真实条目；链接定期巡检
单个方案成本过高中简单方案单阶段；后台任务用小模型；提示缓存；每个方案设成本上限

ビジョンと位置づけ

何をつくるのか、そして意図的に何をつくらないのか

色と重ね着に詳しく、正直に話してくれるスタイリストが、あなたのクローゼットを開けて一緒に考え、いちばん似合う一着をモデルに着せて見せてくれる。

ハッカソンの demo では「服をアップロード → バーチャル試着画像」の流れを検証しました。v2 では重心を試着からスタイリングへ移します。服を人に貼り付けることではなく、どう着るか、なぜ素敵に見えるかを伝え、プロのモデル画像でそれを示すことに価値があります。

  • プロフェッショナル：配色、レイヤード、シルエットと比率、素材の対比を体系的な知識として内蔵し、すべての提案に理由を添えます。
  • 遊び心：無難な提案だけでなく、腰巻き、片袖抜き、アウターの肩掛けなどトレンドの着こなしも提案します。
  • 自律性：プロンプト、生成手順、ブランド検索はすべて Agent が判断します。テンプレートは用意しません。
  • 成長：ファッションコンテンツを読み続け、新しいテクニックをナレッジベースに蓄積します。

スコープ

v2 初回リリースの範囲

やること

  • ユーザーと何往復も対話し、シーン、気分、挑戦したいスタイルを理解する
  • アップロードされた服を分析・タグ付け・登録し、共有クローゼットをつくる
  • ブランド公式サイトから定番品と新作を探し、手持ちの服と組み合わせる
  • アイテム、レイヤー構成、配色の考え方、着こなし、理由まで含む提案を出す
  • 内蔵モデルでプロ品質の着用イメージを生成し、複雑な提案は多段階で生成する
  • ファッション誌からテクニックを抽出し、審査を経てナレッジベースに追加する

やらないこと

  • ユーザーの体型データ（身長、体重、スリーサイズ）の収集や利用
  • ユーザー本人の画像生成、写真ベースのデジタルヒューマン
  • アプリ内での購入と決済（ブランド公式サイトへ遷移のみ）
  • 注文履歴の取込と EC アカウント連携
  • 事前に固定したプロンプトテンプレート

コア機能

6 つの機能はすべてツールとして、ひとつの Agent が使い分けます

KNOW

スタイリング知識

スタイリストの経験を、長いシステムプロンプトに詰め込むのではなく、検索・引用できる構造化知識にします。

  • 色：色相環の配色（同系色、類似色、補色、トライアド）、明度と彩度の段階、ニュートラルカラーの比率、寒暖と季節の色
  • レイヤード：インナー / ミドル / アウター / アクセントの 4 役割、丈・厚み・ゆとりの交互と見せる割合
  • シルエットと比率：H / A / V / X ライン、上ゆる下タイト、3:7 バランス、ウエスト位置
  • 素材と柄：質感の対比、柄の大小の組み合わせ、フォーマル度の統一
  • 知識は 1 件ずつ「テクニックカード」として管理し、提案時にはどのカードを使ったか明記します
CLOSET

クローゼット理解

写真をアップロードすると、切り抜き・分析・タグ付け・登録まで自動で行います。通常の属性に加え、その服の「着こなしポテンシャル」も記録します。

  • 属性：カテゴリ、メインカラーとサブカラー（hex + 比率）、素材、柄、シルエット、フォーマル度、季節、スタイル
  • 着こなしポテンシャル：スウェットは腰巻き、シャツは片袖抜きや羽織り、ニットは肩掛け、ロング T はフロントイン
  • ユーザーはタグを修正でき、修正結果は評価データとして活用します
SCOUT

ブランドアイテム探索

Agent が指定ブランドの公式サイトで定番品と今季の新作を探し、ブランドカタログとしてキャッシュします。手持ちの服と一緒にコーディネートに使います。

  • 必要に応じたリアルタイム検索 + 定期的なバックグラウンド巡回（新作、販売終了、価格変更）
  • 保存するのは構造化メタデータと公式リンクのみ。提案ではカタログに実在するアイテムだけを引用します
COMPOSE

コーディネート提案

会話から得たシーンと好み、クローゼット、ブランドカタログ、テクニックカードを組み合わせて、完成した提案をつくります。

  • 提案の中身：アイテムとレイヤーの役割、配色の考え方、着こなしの詳細、素敵に見える理由、代替アイテム
  • 画像生成の前に、ルール検証ツールで配色とレイヤーの整合性を確認し、無駄な生成を減らします
  • 基本は安心できる提案をひとつ。状況に応じて「意外だけど成立する」提案も添えます
RENDER

自律的な画像生成

プロンプトは Agent が提案内容に合わせてその場で書きます。シンプルな提案は一回で生成し、複雑な提案（重ね着が多い、変わった着こなし）は Agent が複数段階に分けて編集とセルフチェックを繰り返します。詳細は「多段階の画像生成」を参照。

LEARN

自己学習

バックグラウンドの学習 Agent が定期的にファッション誌やコレクションレポートを読み、新しいテクニックを候補カードとしてまとめます。

  • 候補カードは評価セットでの回帰テスト（提案品質が下がらないこと）と人の審査を通過して、はじめて正式なナレッジに入ります
  • 保存するのは自分の言葉でまとめた抽象的なテクニックと出典のみ。本文や画像は保存しません
  • トレンド系のテクニックには有効期限を設け、シーズンが過ぎたら自動で優先度を下げます

多段階の画像生成

複雑な提案での標準フロー。Agent は提案に応じて段階を増減できます

  1. 計画提案を読み、複雑さを判断して構造化された生成計画を出力：段階数、各段階の参照画像、忠実に再現すべきディテール、チェック項目。
  2. ベースのスタイリングモデル参照画像 + インナーとボトムス。色、柄、シルエットの再現を最優先。
  3. レイヤード前段階の結果を編集してアウターを追加。提案どおりの重ね順と見せる割合にする。
  4. 変わった着こなしとディテール腰巻き、片袖抜き、フロントイン、袖まくり、小物を一項目ずつ部分編集し、一度に変えすぎて崩れるのを防ぐ。
  5. セルフチェックと修正ビジョンモデルが計画と照らし合わせて確認：アイテムは正しいか、色は合っているか、着こなしは実現できたか、体の構造は自然か。不合格なら該当段階をやり直すか部分修正。リトライ上限あり。

シンプルな提案（2〜3 アイテムで変わった着こなしなし）は一回で生成してチェックします。うまくいった段階の分け方は「生成ノウハウカード」として蓄積し、次回 Agent が参考にします。ただし固定テンプレートではありません。

内蔵モデルライブラリ

美しく、肖像権や著作権のリスクがない標準モデル

  • 商用利用可能な画像生成モデルで「実在しない人物」を生成します。モデルごとに正面・横・7 分身の参照画像セットを持ち、毎回の生成で本人性の参照に使うことで、同じモデルの見た目を保ちます。
  • 公開前に実在の人物や著名人との類似度をチェックし、モデルカードに生成モデル、日付、ライセンス条件を記録します。
  • 男女とも揃え、複数のスタイル（ストリート、ミニマル、プレッピー、オフィス、エレガントなど）と多様なルーツをカバーします。Agent が提案のスタイルに合わせて選び、ユーザーが指定することもできます。
  • 出力規格を統一：スタジオのソフトライト、無地背景、全身、3:4。Demo で調整した「ポスター品質」の知見は Agent の参考資料として使います。

A stylist who shares your wardrobe

StyleAI v2 is a styling agent that thinks for itself. It understands color and layering, reads every garment you upload, and looks up pieces on brand websites. It writes its own image prompts, decides when a look needs several render passes, and learns new techniques by reading fashion magazines.

Vision & positioning

What we are building, and what we are deliberately leaving out

A style creator who knows color and layering and tells you the truth. They open your closet, talk it through with you, then put the best version of the look on a model so you can see it.

The hackathon demo proved the “upload a garment → virtual try-on” pipeline. v2 moves the focus from try-on to styling. The value isn't in pasting clothes onto a body. It's in telling people how to wear it and why it works, then showing it on a professional model.

  • Expert: Built-in, structured knowledge of color, layering, silhouette and proportion, and texture contrast. Every look comes with its reasoning.
  • Playful: Beyond safe picks, it suggests street-style moves like a hoodie tied at the waist, one sleeve off, or a jacket draped over the shoulders.
  • Autonomous: The agent decides the prompts, the render steps and the brand searches. No prewritten templates.
  • Always learning: It keeps reading fashion content and adds new techniques to its knowledge base.

Scope

Boundaries for the first v2 release

In scope

  • Long, multi-turn conversations to understand the occasion, mood and styles the user wants to try
  • Uploaded garments are analyzed, tagged and saved into a shared wardrobe
  • Classic and new-season pieces found on brand websites, mixed with the user's own clothes
  • Complete looks: pieces, layering, color logic, how to wear each piece, and why it works
  • Professional renders on built-in models, with multi-stage rendering for complex looks
  • Techniques extracted from fashion magazines and added to the knowledge base after review

Out of scope

  • Collecting or using body data (height, weight, measurements)
  • Rendering the user themselves, or avatars built from their photos
  • In-app checkout and payment. We only link out to brand sites
  • Order import and e-commerce account connections
  • Prewritten prompt templates

Core capabilities

Six capabilities, all exposed as tools to a single agent

KNOW

Styling knowledge

A stylist's expertise stored as structured knowledge the agent can search and cite, rather than crammed into one long system prompt.

  • Color: color-wheel schemes (monochrome, analogous, complementary, triadic), value and saturation steps, neutral ratios, warm/cool and seasonal palettes
  • Layering: four roles (base, mid, outer, accent), alternating length, weight and fit, and how much of each layer shows
  • Silhouette & proportion: H / A / V / X lines, loose-over-slim, the 1:3 rule, waistline placement
  • Texture & pattern: material contrast, pattern scale, consistent formality
  • Each technique is a “technique card”, and every look must list the cards it used
CLOSET

Wardrobe understanding

Uploaded photos are cut out, analyzed, tagged and saved automatically. Along with standard attributes, each garment gets a list of alternative ways to wear it.

  • Attributes: category, primary and secondary colors (hex + share), material, pattern, silhouette, formality, season, style
  • Alternative wears: hoodie tied at the waist, shirt worn one sleeve off or open as a layer, knit draped over the shoulders, long tee half-tucked
  • Users can correct tags, and their corrections become evaluation data
SCOUT

Brand scouting

The agent searches selected brand websites for staples and new-season pieces and caches them in a brand catalog. Catalog pieces are styled alongside the user's wardrobe.

  • Live search on demand, plus scheduled background sweeps for new arrivals, sell-outs and price changes
  • Only structured metadata and official links are stored, and looks may only cite items that exist in the catalog
COMPOSE

Outfit composition

Combines the occasion and preferences from the conversation with the wardrobe, the brand catalog and the technique cards to produce complete looks.

  • Each look includes: pieces and their layer roles, color logic, wearing details, why it works, and swap-in alternatives
  • A rules check confirms the color and layering hold together before any image is generated, so fewer renders are wasted
  • One reliable look by default, plus an “unexpected but it works” option when it fits
RENDER

Autonomous rendering

The agent writes each prompt from the look itself. Simple looks render in one pass. For complex ones (heavy layering, unconventional wears) the agent plans several stages and edits and self-checks as it goes. See “Multi-stage rendering”.

LEARN

Self-improvement

A background learning agent regularly reads fashion magazines and runway reports and writes new techniques up as candidate cards.

  • A candidate joins the live knowledge base only after an eval regression (look quality must not drop) and human review
  • We store only abstracted techniques, rewritten in our own words, with their source. Never the original text or images
  • Trend techniques carry an expiry date and are down-weighted automatically once the season passes

Model choice: the strongest model handles conversation and orchestration, where judgment matters. Faster, cheaper models handle the reading-heavy background work that runs in parallel. Every model sits behind a provider interface, so models can be swapped and compared on evals.

Multi-stage rendering

The default flow for complex looks. The agent can add or drop stages per look

  1. PlanRead the look, judge its complexity, and write a structured render plan: how many stages, reference images for each, details that must stay faithful, and what to check.
  2. Base lookModel reference + base layer and bottoms. Color, print and cut accuracy come first.
  3. LayeringEdit the previous result to add outer layers, following the planned layer order and how much of each shows.
  4. Unconventional wears & detailsWaist tie, one sleeve off, half-tuck, rolled sleeves, accessories. One local edit at a time, so no single pass changes too much.
  5. Critique & repairA vision model checks the image against the plan: right pieces, accurate color, the wear actually executed, natural anatomy. On a failure it re-runs the relevant stage or patches locally, up to a retry cap.

Simple looks (two or three pieces, no unconventional wears) render in one pass and then get critiqued. Stage breakdowns that work are saved as “render playbook cards” for the agent to consult next time. They are references, not fixed templates.

Model roster

Striking, standard models with no likeness or copyright risk

  • People who don't exist, generated with an image model licensed for commercial use. Each model has a reference set (front, side, three-quarter) that is passed as the identity reference on every render, so the same model stays consistent.
  • Before launch, each model is screened for resemblance to real people and celebrities. Each model card records the generating model, the date and the license terms.
  • The roster includes men and women across several style archetypes (street, minimal, preppy, workwear, elegant) and a range of ethnicities. The agent picks a model to match the look, and users can choose one themselves.
  • One output spec: soft studio light, seamless backdrop, full body in frame, 3:4. The demo's tuned “poster-grade” rendering notes become reference material for the agent.

Risks & compliance

High-risk items need a decision during M0

RiskLevelMitigation
Magazine copyrightHighExtract only abstract techniques, rewrite them in our own words and record the source. Store no original text or images. Prefer subscribed or licensed sources
Crawling brand sites and using product imagesHighRespect robots.txt and terms of use; prefer official APIs or affiliate product feeds; store metadata and links only; label renders “for illustration”; negotiate licenses before commercial launch
Model likeness and rights to generated imagesHighUse a commercially licensed image model; screen synthetic models for resemblance; record generation source and license
Garment fidelity loss (color, logos, prints)MediumMulti-stage edits + vision critique; local repair for key pieces; fidelity is part of the eval
Unconventional wears fail to renderMediumGive each its own stage; build up verified render playbook cards
Knowledge base drifts or goes staleMediumThree gates: candidate → eval → human review; trend cards expire
Hallucinated products (links or prices that don't exist)MediumLooks may only cite real catalog items; links are re-checked on a schedule
Cost per look too highMediumSingle-pass renders for simple looks; small models for background work; prompt caching; a cost cap per look
